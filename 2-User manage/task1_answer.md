### 3. Права доступа

Права доступа в Linux определяют, кто может читать (r), записывать (w) и выполнять (x) файлы и каталоги.
Три категории пользователей:

1) u (user/owner) — владелец файла
2) g (group) — группа владельца
3) o (others) — все остальные

Три типа прав:
1) r (read) - Читать содержимое, Просматривать список файлов (ls)
2) w (write) - Изменять содержимое, Создавать/удалять файлы в каталоге
3) x (execute) - Запускать как программу, Входить в каталог (cd)

4.2) Почему права 777 избыточны и опасны
1) Нарушение принципа минимальных привилегий — пользователи получают больше прав, чем нужно для работы
2) Риск случайного изменения — любой пользователь может изменить или удалить содержимое
3) Угроза безопасности — если файл содержит конфиденциальные данные, их может прочитать кто угодно
4) Право на выполнение (x) для обычного текстового файла бессмысленно и потенциально опасно

### 7. Ограничения суперпользователя
Есть ли у суперпользователя абсолютная возможность выполнять любые операции?  Нет, существуют ограничения, не связанные с обычными правами доступа к файлам.
1. Immutable flag (неизменяемый атрибут)
* root не может изменить или удалить файл с установленным флагом i (immutable)

2. Сетевые ограничения (firewall, SELinux/AppArmor)
root может быть ограничен политиками безопасности:
* SELinux может запретить доступ к определенным ресурсам даже для root
* AppArmor ограничивает возможности программ
* iptables/nftables может блокировать сетевые соединения

3. Аппаратные ограничения
* Root не может записать данные на физически защищенный от записи диск
* Root не может обойти ограничения BIOS/UEFI
* 
4. Ядерные ограничения
* Некоторые операции требуют специальных возможностей (capabilities), которые могут быть отозваны даже у root в контейнерах или ограниченных средах.
